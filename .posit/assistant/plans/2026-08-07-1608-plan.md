# Plan: DreamLeague bug triage and fixes

## Objective
Set up a repeatable workflow so bugs can be reported one at a time, reproduced, traced to the correct layer, and then fixed with minimal scope.

## What was confirmed
- The project has two main layers:
  - `web/`: React + TypeScript + Vite frontend
  - `R/`: data export pipeline that produces JSON consumed by the web app
- The web app appears to use `web/src/App.tsx` as the main UI entry point and `web/src/data.ts` for derived calculations and bundle loading.
- The export pipeline writes `web/public/data/bundle.json` from R objects in `R/export-dreamleague-json.R`.

## Working approach for each bug
1. Take one bug report at a time.
2. Classify it before changing anything:
   - **UI/state bug**: tab behavior, controls, layout, interaction, rendering
   - **Frontend logic bug**: standings, history, cup rounds, filters, date handling, derived tables
   - **Data/export bug**: incorrect or stale JSON, schema mismatch, preprocessing/export issue in R
3. Reproduce the issue using the user’s description.
4. Trace the smallest likely code path involved.
5. Propose the fix and, after approval to implement, make the narrowest change necessary.
6. Validate against the described bug and check for nearby regressions.

## Likely files to inspect during implementation
- `web/src/App.tsx`
- `web/src/data.ts`
- `web/src/types.ts`
- `R/export-dreamleague-json.R`
- potentially `R/dl-preprocessing-run.R` if the issue originates upstream in generated data

## Initial bug triage checklist
For each reported bug, collect:
- where it appears: League / Teams / BFL Cup / Players taken / History / Diagnostics
- expected behavior
- actual behavior
- whether it happens consistently
- whether it seems data-specific, date-specific, team-specific, or browser-state-specific

## Implementation principles
- Keep fixes narrowly scoped to the reported behavior.
- Prefer fixing root cause over patching display symptoms.
- If the bug depends on exported data, verify whether the issue is in the source R objects, the JSON export, or TypeScript interpretation.
- Be cautious around date parsing and league/cup derived calculations, since those look like likely error-prone areas.

The requested changes are all in the TypeScript app.

Implement in `web/src/App.tsx` and `web/src/styles.css`.
- Reduce vertical spacing between the lines in the Last Updated panel.
- Reduce the font size for the timestamps panel content.

Likely approach:

- Add a dedicated compact text class in `web/src/styles.css` for the Last Updated block instead of tightening all paragraph spacing globally.

Implement in `web/src/styles.css`.

Likely approach:

Likely approach:
